# Bug 18 — N+1 query in `neoblogger-users list --role author`

**File:** `neoblogger/cli/users.py`
**Severity:** LOW (performance / algorithm)

## Description

In `neoblogger/cli/users.py:60-75`, `_run_list()` fetches all members (`await context.members.all()`) and, when `--role author` is passed, executes `await context.articles.count_by_author(member["display_name"])` inside the `for` loop:

```python
# neoblogger/cli/users.py:60-75
members = await context.members.all()
filtered: list[MemberDocument] = []
for member in members:
    ...
    if args.role == "author":
        counts = await context.articles.count_by_author(member["display_name"])
        if (counts["published"] + counts["draft"]) < 1:
            continue
    filtered.append(member)
```

## Impact

- For $N$ members, `neoblogger-users list --role author` executes $1 + N$ database queries (including $N$ `$facet` aggregation pipelines and $N$ thread-pool hops) instead of 2 queries total.

## Suggested Fix

- Query the set of distinct article authors once before the loop (e.g., `authors = set(connection.articles.distinct("author"))` or a single `$group` by `$author`) and check `if member["display_name"] not in authors: continue` in $O(1)$ time.
