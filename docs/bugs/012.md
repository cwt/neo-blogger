# Bug 12 — Weak scalar validation in `config.py` accepts booleans as ints, non-positive limits, and unknown cache storage modes

**File:** `neoblogger/app/config.py`
**Severity:** MEDIUM

## Description

`_ScalarSection` in `neoblogger/app/config.py:56-139` defines configuration models with unconstrained scalar types (`int`, `str`, `bool`) and non-strict Pydantic validation:

```python
# neoblogger/app/config.py:80-88
for key, value in raw.items():
    annotation = cls.model_fields[key].annotation
    adapter: TypeAdapter[Any] = TypeAdapter(annotation)
    try:
        adapter.validate_python(value)
    except ValidationError:
        continue
    resolved[key] = value
return cls.model_validate(resolved)
```

This leads to three configuration edge cases:

1. **Booleans coerced to `int` (`True` → `1`, `False` → `0`):**
   In Python, `bool` is a subclass of `int`, and Pydantic's non-strict `int` validator accepts `True`/`False` (or numeric strings `"20"`) as valid integers. Setting `per_page = true` or `port = false` in `neo-blogger.toml` sets `per_page = 1` or `port = 0` instead of degrading the wrong-typed field to its documented default (`10` / `8000`).
2. **Zero or negative limits accepted:**
   `PostsConfig` (`per_page`, `max_per_page`), `CacheConfig` (`timeout_seconds`, `max_size_mb`), `UploadConfig` (`max_body_bytes`), and `ApplicationConfig` (`port`) have no `Field(ge=1)` / `Field(ge=1, le=65535)` constraints. Setting `max_body_bytes = -1` causes every image upload to fail with `"the image is too large"`, and setting `timeout_seconds = -1` causes every cached entry to expire immediately.
3. **Unknown `CacheConfig.storage` values accepted:**
   `CacheConfig.storage` is typed as `str = "memory"` instead of `Literal["memory", "file"] = "memory"`. A typo such as `storage = "files"` or `storage = "disk"` passes validation and silently falls through `if self._storage == "file":` in `ResponseCache`, running in-memory per-worker caches instead of shared file caching.

## Impact

- Invalid or mistyped scalar values in `neo-blogger.toml` do not degrade to their documented defaults as required by [Functional Requirements](../requirements.md) §18 (*"Missing values never crash the platform; each subsystem degrades to its documented default"*).

## Suggested Fix

- Enable `strict=True` on `_ScalarSection.model_config = ConfigDict(extra="forbid", strict=True)` and pass `strict=True` to `adapter.validate_python(value, strict=True)`.
- Constrain `CacheConfig.storage` to `Literal["memory", "file"] = "memory"` and add `Field(ge=1)` (and `le=65535` on `port`) to positive integer fields so out-of-range values fail validation and cleanly degrade to their documented defaults.
