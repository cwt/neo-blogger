# Bug 9 — `neoblogger-users set-role` can revoke `publisher` from the sole administrator

**Files:** `neoblogger/cli/users.py`, `neoblogger/app/blueprints/admin.py`
**Severity:** MEDIUM

## Description

[Functional Requirements](../requirements.md) §2 defines the sole-administrator publisher rule:

> "If there is exactly one administrator and that administrator is not yet a publisher, the platform quietly grants publisher status to them at startup"

And the web admin UI (`neoblogger/app/blueprints/admin.py:100-104`) enforces that the sole administrator cannot have `publisher` revoked:

```python
# neoblogger/app/blueprints/admin.py:100-104
if not granted and target["administrator"]:
    stats = await context.members.dashboard()
    if stats.get("admins", 0) <= 1:
        await flash("The sole administrator must remain a publisher.", "error")
        return redirect("/admin")
```

However, in `neoblogger/cli/users.py:310-322` (`_run_set_role()`):

```python
# neoblogger/cli/users.py:310-322
if args.admin is not None:
    if not args.admin and member["administrator"]:
        stats = await context.members.dashboard()
        if stats["admins"] <= 1:
            name = member["display_name"]
            print(
                f"Cannot demote the sole administrator {name!r}.",
                file=sys.stderr,
            )
            return 1
    await context.members.set_administrator(member["_id"], args.admin)
if args.publisher is not None:
    await context.members.set_publisher(member["_id"], args.publisher)
```

`_run_set_role()` checks `stats["admins"] <= 1` when `--no-admin` is passed, but does **not** check it when `--no-publisher` (`args.publisher is False`) is passed for the sole administrator.

Additionally, if a second member is promoted to administrator without `publisher` (`POST /admin/members/<id>/promote` in `admin.py:84` or `neoblogger-users set-role bob --admin`) and the first administrator is subsequently demoted via CLI (`neoblogger-users set-role alice --no-admin`), the remaining sole administrator (`bob`) is left with `publisher=False` until the next process restart triggers `backfill_sole_admin_publisher()`.

## Impact

- Running `neoblogger-users set-role <sole-admin> --no-publisher` strips publisher status from the sole administrator and hides their published articles from all public surfaces until the server is restarted.

## Suggested Fix

- In `neoblogger/cli/users.py:_run_set_role()`, reject `--no-publisher` when the target will remain the sole administrator, and ensure that if a demotion leaves a single remaining administrator, `backfill_sole_admin_publisher()` (or equivalent check) keeps the sole administrator a publisher.
