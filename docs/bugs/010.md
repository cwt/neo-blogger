# Bug 10 — Missing UI and SEO elements required by specification

**Files:** `neoblogger/app/web/static/app.js`, `neoblogger/app/web/templates/admin.html`, `neoblogger/app/web/templates/article.html`, `neoblogger/app/web/templates/profile.html`, `neoblogger/app/web/templates/upload.html`
**Severity:** MEDIUM

## Description

Cross-referencing the templates and client script against [Functional Requirements](../requirements.md) and [Technical Requirements](../technical-requirements.md) reveals six missing UI/metadata elements:

| # | Requirement Reference | Expected Behavior | Current Implementation |
|---|---|---|---|
| 1 | [Functional Requirements](../requirements.md) §4.5, §5.4, §6, §7, §10.5; [Technical Requirements](../technical-requirements.md) §10 | `<dialog>`-based confirmation modal before deleting an article, comment, or image | `profile.html:28`, `article.html:41`, and `upload.html:25` submit delete `<form>`s immediately with no `<dialog>` or confirmation prompt in `app.js` |
| 2 | [Functional Requirements](../requirements.md) §10.1, §10.3 | Copy-URL button on the post-upload banner and on each gallery card in `/upload` | `app.js:34-43` binds `[data-copy-url]`, but `upload.html` renders no `[data-copy-url]` buttons (see also [Bug 22](022.md)) |
| 3 | [Functional Requirements](../requirements.md) §6; [Technical Requirements](../technical-requirements.md) §7 | Lightweight formatting toolbar on the comment form (`article.html`) | `article.html:54` renders a plain `<textarea id="comment-text">` with no toolbar |
| 4 | [Functional Requirements](../requirements.md) §3.10, §11.3 | Admin navigation link to the unpublished articles review page (`/admin/unpublished`) | Neither `admin.html` nor `base.html` contains any `<a href="/admin/unpublished">` link; the page is unreachable via UI navigation |
| 5 | [Functional Requirements](../requirements.md) §11.1 | Admin Dashboard stat cards: *members (total, active, administrators, publishers) and content (total articles, published articles, drafts, total comments)* | `admin.html:5-13` renders 7 cards, omitting **total articles** (`articles.published + articles.draft`) |
| 6 | [Functional Requirements](../requirements.md) §16; [Technical Requirements](../technical-requirements.md) §13 | Per-article `<meta name="keywords">` and `<meta property="article:tag">` topic markers | `article.html:7-15` emits `og:type`, `og:title`, `og:description`, `og:image`, and `article:published_time`, but omits `keywords` and `article:tag` |

Additionally, `admin.html:27-31` renders a "Disable" button on administrator rows (including the signed-in administrator's own row) even though [Functional Requirements](../requirements.md) §11.2 specifies *"A table of all other members... An administrator can never disable another administrator."*

## Impact

- Destructive delete actions execute on a single click without confirmation.
- Administrators cannot navigate to `/admin/unpublished` without typing the URL manually.
- Users on `/upload` cannot use the one-click Copy-URL button described in the spec.
- Article pages miss standard `keywords` and `article:tag` SEO meta tags.

## Suggested Fix

1. Add a shared `<dialog>` confirmation modal in `base.html` and wire delete forms in `app.js` (progressive enhancement: forms still work without JS).
2. Add `<button type="button" data-copy-url="/images/{{ image.id }}.webp">Copy URL</button>` to each gallery card in `upload.html`.
3. Attach the lightweight EasyMDE toolbar (bold, italic, link, code, preview) to `#comment-text` in `article.html` / `app.js`.
4. Add a link to `/admin/unpublished` and the total articles stat card (`{{ articles.published + articles.draft }}`) in `admin.html`, and hide the Disable button on administrator rows.
5. Add `<meta name="keywords" content="{{ article.tags | join(', ') }}">` and `{% for tag in article.tags %}<meta property="article:tag" content="{{ tag }}">{% endfor %}` to `article.html`.
