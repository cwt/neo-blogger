# Bug 4 — Startup `backfill_author_snapshots` omits `comments.author_active`

**File:** `neoblogger/app/repositories/db.py`
**Severity:** HIGH

## Description

Per [Technical Requirements](../technical-requirements.md) §5.8 (Spike S7):

> "articles and comments carry denormalized author-state snapshots (`author_active`, `author_publisher`, `author_active` on comments): stamped inside the atomic save work unit, resynced on every role/account toggle (§11.2), recomputed idempotently at startup (§19.6)."

While `ArticleVisibility.resync_author_articles()` (`neoblogger/app/services/visibility.py:110-119`) updates both `articles` and `comments`, the startup backfill in `neoblogger/app/repositories/db.py:159-178` only updates `connection.articles` and completely ignores `connection.comments`:

```python
# neoblogger/app/repositories/db.py:159-178
def backfill_author_snapshots(connection: Any) -> None:
    articles = connection.articles
    changed = 0
    for member in list(connection.members.find({})):
        snapshots = {
            "author_active": bool(member.get("active", False)),
            "author_publisher": bool(member.get("publisher", False)),
        }
        result = articles.update_many(
            {"author": member["display_name"]}, {"$set": snapshots}
        )
        changed += result.modified_count
```

Additionally, `backfill_articles()` (`neoblogger/app/repositories/db.py:113-127`) does not backfill missing `author_active` fields on legacy comment documents where `{"author_active": {"$exists": False}}`.

## Impact

- Legacy comments missing `author_active` or comments whose author's `active` flag was modified out-of-band are not repaired at startup.
- Because `CommentService.list()` filters non-admin views by `{"author_active": True}`, legacy comments without `author_active` are silently hidden from public view, or comments by a disabled member remain visible if `author_active` stayed `True`.

## Suggested Fix

- In `backfill_author_snapshots()` (`neoblogger/app/repositories/db.py:159-178`), also resync `connection.comments.update_many({"author": member["display_name"]}, {"$set": {"author_active": bool(member.get("active", False))}})` (and default any remaining comments where `{"author_active": {"$exists": False}}` to `True`).
- See also [Bug 19](019.md) for optimizing the per-member startup loop.
