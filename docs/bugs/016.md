# Bug 16 — Missing database indexes on hot filter fields (`author_active`, `author_publisher`, `metadata.owner`)

**File:** `neoblogger/app/repositories/db.py`
**Severity:** MEDIUM (performance)

## Description

[Functional Requirements](../requirements.md) §14 states:

> "All hot query paths are covered by the indexes listed in the Data Model."

And [Technical Requirements](../technical-requirements.md) §5.8 (Spike S7) introduced denormalized `author_active` and `author_publisher` snapshot fields specifically so *"Feed/search filters stay single-round-trip indexed matches (§14)."*

However, `ensure_indexes()` in `neoblogger/app/repositories/db.py:72-104` never declares indexes on those snapshot fields or on the GridFS gallery query fields:

1. **Public feed & sitemap filter (`PUBLIC_FEED_FILTER`):**
   Queries `{"status": "published", "author_active": True, "author_publisher": True}` sorted by `created DESC`. Only `(status, created DESC)` is indexed (`db.py:82`), missing `(status, author_active, author_publisher, created DESC)`.
2. **Unpublished articles review (`ArticleRepository.unpublished_review`, `articles.py:298-301`):**
   Queries `{"author_publisher": False}` sorted by `created DESC`, with no index on `author_publisher` or `(author_publisher, created DESC)`.
3. **Visible comments per article (`CommentRepository.for_article`, `comments.py:91-95`):**
   Queries `{"$and": [{"article_id": article_id}, {"author_active": True}]}` sorted by `created DESC`. Only `(article_id, created DESC)` is indexed (`db.py:94`), missing `(article_id, author_active, created DESC)`.
4. **Gallery & theme banner listing (`ObjectRepository.list_for`, `objects.py:111-118`):**
   Queries `connection.fs.files` with `{"metadata.owner": owner}` sorted by `uploadDate DESC`, with no index on `metadata.owner`.

## Impact

- As articles, comments, and uploaded images grow, public feed queries, `/admin/unpublished`, comment listings, and `/upload` gallery pagination perform post-index filter scans or full table scans.

## Suggested Fix

In `ensure_indexes()` (`neoblogger/app/repositories/db.py:72-104`), add idempotent compound indexes:
- `articles.create_index([("status", ASCENDING), ("author_active", ASCENDING), ("author_publisher", ASCENDING), ("created", DESCENDING)])`
- `articles.create_index([("author_publisher", ASCENDING), ("created", DESCENDING)])`
- `comments.create_index([("article_id", ASCENDING), ("author_active", ASCENDING), ("created", DESCENDING)])`
- `connection.fs.files.create_index("metadata.owner")`
