# Bug 20 — $O(N)$ linear scans on every `ResponseCache` memory access and eviction

**File:** `neoblogger/app/services/cache.py`
**Severity:** LOW (algorithm / performance)

## Description

In `neoblogger/app/services/cache.py`:

1. **`_oldest_memory_key()` (`cache.py:202-208`) scans all entries linearly inside a `while` loop (`cache.py:160-170`):**
   ```python
   def _oldest_memory_key(self) -> str:
       oldest_key = ""
       oldest_time = float("inf")
       for key, entry in self._entries.items():
           if entry.stored_at < oldest_time:
               oldest_key, oldest_time = key, entry.stored_at
       return oldest_key
   ```
   Evicting $K$ entries when a large response is cached takes $O(K \cdot N)$ time.
2. **`_sweep_expired_memory()` (`cache.py:192-200`) scans all entries on every `get()` and `put()`:**
   ```python
   def _sweep_expired_memory(self) -> None:
       now = time.monotonic()
       expired = [
           key
           for key, entry in self._entries.items()
           if now - entry.stored_at > self._timeout
       ]
       for key in expired:
           self._evict_memory_key(key)
   ```

Because `put()` pops existing keys before re-inserting (`if key in self._entries: self._evict_memory_key(key)` at line 150) and `time.monotonic()` is monotonically non-decreasing, Python's insertion-ordered `dict` (`self._entries`) is already strictly ordered from oldest `stored_at` to newest `stored_at`.

## Impact

- Unnecessary $O(N)$ full-dict iterations on every cache hit/write and $O(K \cdot N)$ eviction loops when `O(1)` head-of-dict operations suffice.

## Suggested Fix

- Replace `_oldest_memory_key()` with `next(iter(self._entries), "")` ($O(1)$).
- In `_sweep_expired_memory()`, iterate from the front of `self._entries` and `break` at the first entry where `now - entry.stored_at <= self._timeout` (amortized $O(1)$ per insertion).
