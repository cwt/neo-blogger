# Bug 6 — File-backed `ResponseCache` runs blocking disk I/O on the event loop and skips startup cache clear

**Files:** `neoblogger/app/services/cache.py`, `neoblogger/app/wiring.py`
**Severity:** MEDIUM

## Description

1. **Blocking disk I/O inside `async def` methods (`neoblogger/app/services/cache.py:90-146, 174-185`):**
   - `ResponseCache.get()` executes synchronous `file_path.exists()`, `file_path.read_text()`, `file_path.stat()`, and `file_path.unlink()` directly on the asyncio event loop.
   - `ResponseCache.put()` executes synchronous `self._directory.mkdir()`, `_sweep_expired_files()` (which globs and calls `stat()`/`unlink()` on every `*.cache` file in the directory), `NamedTemporaryFile` synchronous write + `replace()`, and `_enforce_file_cap()` (which again globs and `stat()`s every `*.cache` file) directly on the event loop.
   - `ResponseCache.clear()` executes synchronous `glob("*.cache")` and `unlink()` when called from `async def _finalize` (`neoblogger/app/wiring.py:348`).

2. **Missing cache clear on startup (`neoblogger/app/wiring.py:188-213`):**
   [Functional Requirements](../requirements.md) §14 and [Technical Requirements](../technical-requirements.md) §3.4 step 5 state:
   > "On startup the platform clears the cache, then pre-warms it by rendering the first home-feed page for anonymous visitors"
   
   In `neoblogger/app/wiring.py:188-213`, `_prewarm()` never calls `cache.clear()`. Worse, in `file` storage mode, if `.cache` files remain on the persistent volume from a previous run with the same `content_version`, lines 204–206 (`cached = await cache.get(key, version); if cached is not None: return`) short-circuit pre-warming and keep serving stale HTML from before the restart (e.g., after template, theme, or config changes).

## Impact

- In multi-worker production deployments using `storage = "file"` ([Technical Requirements](../technical-requirements.md) §15.4), every cache read, write, sweep, and eviction performs synchronous filesystem syscalls on the event loop.
- Restarting the container (e.g., after generating theme banners via `neoblogger-theme generate` per `README.md:140`) fails to evict existing file-cached pages because `content_version` is unchanged and `_prewarm()` does not clear the cache.

## Suggested Fix

- Call `cache.clear()` at startup before pre-warming (or bump `content_version` / clear on boot).
- Offload file-backed cache operations (`get`, `put`, `clear`) via `asyncio.to_thread(...)` so filesystem I/O never blocks the event loop.
