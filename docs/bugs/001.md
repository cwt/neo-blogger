# Bug 1 — CPU-bound Argon2id hashing runs synchronously on the event loop

**Files:** `neoblogger/app/services/accounts.py`, `neoblogger/app/security/hashing.py`
**Severity:** HIGH

## Description

`hash_secret()` and `verify_secret()` in `neoblogger/app/security/hashing.py:15-28` invoke `argon2.PasswordHasher.hash()` and `.verify()` synchronously. `AccountService` in `neoblogger/app/services/accounts.py` calls these functions directly inside `async def` methods on the main asyncio event loop thread without offloading to a thread pool executor:

- `AccountService.register()` (`neoblogger/app/services/accounts.py:85-86`) runs **two** sequential Argon2id hashes (`hash_secret(password)` and `hash_secret(normalize_answer(answer))`).
- `AccountService.authenticate()` (`neoblogger/app/services/accounts.py:104`) runs `verify_secret(member["password_hash"], password)`.
- `AccountService.recover()` (`neoblogger/app/services/accounts.py:120-122`) runs `verify_secret(...)` followed by `hash_secret(new_password)`.
- `AccountService.update_credentials()` (`neoblogger/app/services/accounts.py:153-155`) runs up to two `hash_secret(...)` calls.

```python
# neoblogger/app/services/accounts.py:85-86
password_hash = hash_secret(password)
answer_hash = hash_secret(normalize_answer(answer))
```

This violates the blocking-work policy in [Technical Requirements](../technical-requirements.md) §2 and §5.6:

> "Every route is `async def`; blocking work must never run on the event loop (see §5.6)."
> "Nothing blocking may run inside an `async def` route directly."

## Impact

- Argon2id is intentionally CPU- and memory-hard (~50–100 ms per hash/verify call on typical server hardware).
- During registration, sign-in, password recovery, or profile editing (~100–200 ms for dual-hash paths), the worker's asyncio event loop is completely blocked.
- All concurrent requests on that worker process (including `/healthz` probes, static asset serving, and cached home-feed responses) stall until hashing finishes.

## Suggested Fix

- Offload `hash_secret()` and `verify_secret()` calls via `asyncio.to_thread(...)` (or the CPU executor in `AppContext`) inside `AccountService` and `neoblogger/cli/users.py`, or provide async wrappers `async_hash_secret` / `async_verify_secret`.
- When hashing both password and security answer in `register()` and `update_credentials()`, run both offloaded hashes concurrently via `asyncio.TaskGroup`.
