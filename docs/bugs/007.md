# Bug 7 — Deploy-time theme banners leak into the Admin Upload Gallery & Cover Picker and break `context.theme_banners` if deleted

**Files:** `neoblogger/app/repositories/objects.py`, `neoblogger/app/blueprints/images.py`, `neoblogger/app/blueprints/blog.py`, `neoblogger/app/wiring.py`
**Severity:** MEDIUM

## Description

Deploy-time theme artwork generated by `neoblogger-theme generate` stores 10 page-family banner images in GridFS with `metadata.owner = "theme"` and `metadata.theme_banner = <page_family>`.

When an administrator opens the Upload Image gallery (`/upload`, `neoblogger/app/blueprints/images.py:106-107`) or the Write Article cover picker (`/write`, `neoblogger/app/blueprints/blog.py:142-145`), `owner` is passed as `None`:

```python
# neoblogger/app/blueprints/images.py:106-107
owner = None if g.member["administrator"] else g.member["display_name"]
rows, total = await context.objects.list_for(owner, page, _GALLERY_PAGE_SIZE)
```

In `ObjectRepository.list_for()` (`neoblogger/app/repositories/objects.py:111`):

```python
query = {"metadata.owner": owner} if owner else {}
```

Because `query` is `{}` when `owner is None`, all 10 `"theme"`-owned system banners appear at the top of the administrator's 12-item upload gallery and 48-item article cover picker.

Furthermore, `context.theme_banners` is loaded only once (`if context.theme_banners is None:` in `neoblogger/app/wiring.py:95`). If an administrator deletes a theme image from `/upload`, the deletion guard in `ObjectsService.delete()` (`neoblogger/app/services/objects.py:172-195`) only checks `articles.cover_url`, allows the deletion, and leaves `context.theme_banners` pointing to `/images/<deleted_id>.webp`, which returns `404 Not Found` on every page in that family until the server restarts.

## Impact

- System theme banners clutter the administrator's image gallery and article cover picker.
- Deleting a theme banner via the web UI silently breaks the site header banner with a 404 image until process restart.

## Suggested Fix

- Exclude `"theme"`-owned objects (`{"metadata.owner": {"$ne": "theme"}}`) when `owner is None` in gallery/cover-picker listings, or add a dedicated `exclude_owner: str | None = THEME_OWNER` parameter on `list_for()`.
- In `ObjectsService.delete()` (or `images.py:delete`), either refuse deletion of `"theme"`-owned system banners via the web UI (requiring `neoblogger-theme generate --force`) or invalidate `context.theme_banners = None` when a theme object is removed.

**Status:** Fixed (see [Bug Tracker](index.md)).
