# Bug 17 — `GridFSBucket` re-instantiated on every object store operation

**File:** `neoblogger/app/repositories/objects.py`
**Severity:** LOW (performance)

## Description

`ObjectRepository._bucket()` (`neoblogger/app/repositories/objects.py:27-29`) creates a brand-new `GridFSBucket` instance on every call to `upload()`, `data()`, `delete()`, and `list_for()`:

```python
# neoblogger/app/repositories/objects.py:27-29
def _bucket(self) -> GridFSBucket:
    """The bucket instance on the connection."""
    return GridFSBucket(self._database.connection)
```

Meanwhile, `ensure_indexes()` (`neoblogger/app/repositories/db.py:101-103`) already instantiates `GridFSBucket(connection)` once at startup to initialize the `fs_files` and `fs_chunks` tables and indexes.

## Impact

- Every image serve (`/images/<id>.webp`), upload, delete, and gallery listing repeats `GridFSBucket.__init__()` schema/index verification work on the single-threaded DB executor.

## Suggested Fix

- Store the initialized `GridFSBucket` instance on `Database` during `start()` (and clear it in `close()`), or cache it per connection on `ObjectRepository`.

**Status:** Fixed (see [Bug Tracker](index.md)).
