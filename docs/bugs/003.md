# Bug 3 — Missing server-side input validation on articles, comments, cover URLs, and emails

**Files:** `neoblogger/app/services/articles.py`, `neoblogger/app/services/comments.py`, `neoblogger/app/services/accounts.py`, `neoblogger/cli/users.py`
**Severity:** HIGH

## Description

[Functional Requirements](../requirements.md) §1.3 mandates:

> "Safe by default. All user-supplied content is treated as untrusted. Rendering, searching, uploading, and moderating must be built around explicit allowlists and server-side validation."

Several write paths rely solely on client-side HTML attributes (`required`, `maxlength`, `type="email"`) with no server-side validation:

1. **Article fields (`neoblogger/app/services/articles.py:51-114`):**
   - `ArticleService.save()` does not verify that `title`, `subtitle`, or `body` are non-empty after stripping, nor does it enforce maximum lengths (`title <= 200`, `subtitle <= 300`, `display_name <= 50`).
   - When EasyMDE is active on `/write`, the underlying `<textarea id="body" required>` is hidden; submitting without typing or via direct `POST /write` stores an article with empty `title`, `subtitle`, or `body`.
2. **Cover image URL scheme (`neoblogger/app/services/articles.py:71-72`):**
   - `cover_url` is accepted without scheme or path validation. Arbitrary values (such as `javascript:alert(1)` or `data:text/html,...`) can be saved and rendered directly into `<img src="{{ article.cover_url }}">` (`_feed_cards.html:7`, `article.html:23`, `profile.html:18`) and `<link rel="preload" as="image" href="{{ article.cover_url }}">` (`article.html:8`).
3. **Comment text (`neoblogger/app/services/comments.py:29-48`):**
   - `CommentService.add()` does not check `if not text.strip():`, allowing empty or whitespace-only comments to be persisted via `POST /articles/<id>/comments`.
4. **Email format (`neoblogger/app/services/accounts.py:68-72, 142-144`, `neoblogger/cli/users.py:172-178, 373-376`):**
   - `register()`, `update_credentials()`, and `neoblogger-users` only check `if not email:`, accepting strings without `@` or a domain part.

## Impact

- Blank articles and blank comments can be created and published via direct HTTP POST requests or when client-side validation is bypassed.
- Unvalidated `cover_url` values pollute `<img src>`, `<link rel="preload">`, Open Graph `<meta property="og:image">`, and JSON-LD output.
- Malformed email strings can be stored via the web forms or CLI.

## Suggested Fix

- In `ArticleService.save()`: validate `title.strip()`, `subtitle.strip()`, and `body.strip()` are non-empty; enforce length caps; validate `cover_url` (when non-empty) starts with `/images/` or `https://` / `http://`.
- In `CommentService.add()`: raise `ValueError("comment text is required")` when `not text.strip()`.
- In `AccountService.register()`, `AccountService.update_credentials()`, and `cli/users.py`: validate basic email syntax (`"@" in email` with non-empty local and domain parts) and `len(display_name) <= 50`.
