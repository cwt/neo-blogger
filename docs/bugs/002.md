# Bug 2 — Re-drafting a published article and deleting it leaks orphaned comments; drafts accept comments

**Files:** `neoblogger/app/services/articles.py`, `neoblogger/app/blueprints/blog.py`
**Severity:** HIGH

## Description

Two interacting defects allow comments to be orphaned in the `comments` collection:

1. **Skipping cascade delete on re-drafted articles (`neoblogger/app/services/articles.py:116-121`):**
   `ArticleService.delete()` only deletes comments when `article["status"] == "published"`:

   ```python
   # neoblogger/app/services/articles.py:116-121
   async def delete(self, article: ArticleDocument) -> None:
       """Cascade comments for published articles and remove the document (§5.4)."""
       if article["status"] == "published":
           await self._visibility.delete_comments_for(article["_id"])
       await self._articles.delete(article["_id"])
       await self._meta.bump_content_version()
   ```

   Per [Functional Requirements](../requirements.md) §5.2: *"An article can also be re-drafted from published state by saving it with the draft action."* If a published article accumulates comments, is subsequently re-drafted by its author, and is then deleted while in `draft` status, `delete_comments_for` is skipped.

2. **Drafts accept comments (`neoblogger/app/blueprints/blog.py:165-168`):**
   `add_comment()` checks `context.visibility.can_view(g.member, article)` rather than verifying `article["status"] == "published"`:

   ```python
   # neoblogger/app/blueprints/blog.py:165-168
   article = await context.articles.by_id(article_id)
   if article is None or not context.visibility.can_view(g.member, article):
       await flash("That content is not available.", "error")
       return redirect("/")
   ```

   Because `can_view()` returns `True` for the draft's author and for administrators, both can submit `POST /articles/<draft_id>/comments` to attach comments to an unpublished draft, contradicting [Functional Requirements](../requirements.md) §5.4 (*"drafts cannot accumulate comments"*).

## Impact

- Orphaned comment documents remain permanently in the `comments` collection after their parent article is deleted.
- Admin Dashboard total comment counts (`comments.total()`) and member Profile statistics (`comments.count_by_author()` and `contributions`) are permanently inflated by unreachable comments.

## Suggested Fix

1. In `ArticleService.delete()` (`neoblogger/app/services/articles.py:118`), always run `await self._visibility.delete_comments_for(article["_id"])` unconditionally (it is an indexed `delete_many({"article_id": article_id})` no-op when zero comments exist).
2. In `add_comment()` (`neoblogger/app/blueprints/blog.py:166`) and `CommentService.add()` (`neoblogger/app/services/comments.py:36`), reject commenting when `article.get("status") != "published"`.
