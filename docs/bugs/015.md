# Bug 15 — Sequential DB executor round-trips on `/admin`, `/<article_id>`, `/tag/<name>`, and `/profile`

**Files:** `neoblogger/app/blueprints/admin.py`, `neoblogger/app/blueprints/blog.py`, `neoblogger/app/blueprints/discovery.py`, `neoblogger/app/blueprints/profile.py`, `neoblogger/app/services/accounts.py`
**Severity:** MEDIUM (performance / architecture)

## Description

[Functional Requirements](../requirements.md) §14 and [Technical Requirements](../technical-requirements.md) §2 & §5.3 mandate:

- *"article pages fetch the article and its active-member comments in one joined query (`$lookup`, or equivalent supported by the engine)."* (§5.3)
- *"Dashboard statistics: minimal round trips via grouped pipelines (spec §11.1)."* (§5.3)
- *"`asyncio.TaskGroup` + `asyncio.timeout()`: all structured concurrency (e.g. dashboard statistics, parallel repository reads) must use TaskGroups."* (§2)

Currently, `asyncio.TaskGroup` is not used anywhere in `neoblogger/`, and several hot routes issue multiple sequential `loop.run_in_executor` round-trips:

1. **Article page (`neoblogger/app/blueprints/blog.py:70, 77`):**
   Issues 2 separate executor hops (`await context.articles.by_id(article_id)` then `await context.comment_service.list(article, g.member)`) instead of a single joined `$lookup` pipeline (verified in `tools/spikes/spike_s2.py` Check S2-2) or a single executor work unit.
2. **Admin dashboard (`neoblogger/app/blueprints/admin.py:29-38`):**
   Issues 4 sequential executor hops:
   ```python
   member_stats = await context.members.dashboard()
   article_stats = await context.articles.count_by_status()
   comments_total = await context.comments.total()
   ...
   member_rows = await context.members.all()
   ```
3. **Tag page (`neoblogger/app/blueprints/discovery.py:25-28`):**
   Issues 2 sequential executor hops (`await context.article_service.tag_page(...)` then `await context.article_service.related_tags(...)`).
4. **Profile page (`neoblogger/app/blueprints/profile.py:23-24`, `neoblogger/app/services/accounts.py:169-170`):**
   Issues 3 sequential executor hops (`articles.count_by_author()`, `comments.count_by_author()`, and `articles.for_author()`).

## Impact

- Each separate `await self._database.run(...)` call incurs event-loop scheduling and thread-hop overhead, and allows other requests' DB tasks to interleave between reads on the same page.

## Suggested Fix

- Use `asyncio.TaskGroup` for independent concurrent reads in the service/blueprint layers per [Technical Requirements](../technical-requirements.md) §2, and combine tightly coupled reads (such as article + visible comments, or profile counts + recent posts) into single repository work units or `$lookup`/`$facet` pipelines per §5.3.

**Status:** Fixed (see [Bug Tracker](index.md)).
