# Bug 5 — Broken `og:image` and JSON-LD image URL generation on article pages

**Files:** `neoblogger/app/web/templates/article.html`, `neoblogger/app/blueprints/blog.py`, `neoblogger/app/blueprints/seo.py`, `neoblogger/app/services/objects.py`
**Severity:** HIGH

## Description

Three defects affect social-preview and structured-data image URLs on article pages:

1. **Concatenating `request.url_root` onto already-absolute URLs (`neoblogger/app/web/templates/article.html:13`):**
   ```html
   {% if g.article.image %}<meta property="og:image" content="{{ request.url_root.rstrip('/') }}{{ g.article.image }}">{% endif %}
   ```
   When `article["cover_url"]` is an absolute URL (such as `https://x.io/c.webp`), `article.html` produces an invalid concatenated URL:
   ```html
   <meta property="og:image" content="http://localhosthttps://x.io/c.jpg">
   ```
   The existing test in `tests/test_web_seo.py:151` only asserted `assert '<meta property="og:image" content="http' in rendered`, which matched the broken prefix `http://localhosthttps://...`.

2. **Rewriting extensions on external URLs (`neoblogger/app/services/objects.py:79-84`):**
   `legacy_url(image_url)` blindly replaces `.webp` with `.jpg` on any URL string:
   ```python
   def legacy_url(image_url: str, extension: str = "jpg") -> str:
       root, dot, _extension = image_url.rpartition(".")
       if not dot:
           return image_url
       return f"{root}.{extension}"
   ```
   On-the-fly `.jpg` conversion only exists for Neo-Blogger's own `/images/<id>.<ext>` route. Rewriting an external URL `https://cdn.example.com/photo.webp` to `https://cdn.example.com/photo.jpg` points crawlers to a 404 on the external server.

3. **Ignoring `application.base_url` and `ProxyTrust` (`neoblogger/app/web/templates/article.html:13`, `neoblogger/app/blueprints/seo.py:50`):**
   [Functional Requirements](../requirements.md) §18 specifies:
   > "external base URL (with trailing-slash normalization; required for correct shared-image and preview URLs in production)"
   Yet `article.html:13` uses `request.url_root` directly (ignoring `base_url` and `X-Forwarded-Proto`/`X-Forwarded-Host`), and `jsonld_document()` (`seo.py:50`) emits a relative `/images/<id>.jpg` path for local covers instead of a canonical absolute URL.

## Impact

- Social link previews (Open Graph) and JSON-LD `Article.image` metadata contain malformed or unreachable URLs in production behind a reverse proxy or when external cover URLs are used.

## Suggested Fix

- Only apply `legacy_url()` when the cover URL targets the local `/images/<24-hex>.webp` endpoint.
- Resolve `g.article["image"]` to a full canonical absolute URL in `blog.py` using `canonical_url_for(context.config.application.base_url, request_base(context.proxy_trust), path)` when `image` is a relative path, and pass it directly to both `<meta property="og:image" content="{{ g.article.image }}">` and `jsonld_document()`.
